# 任务环境清理

适用于装点猫管理后台收到「任务完成」或「今天工作完成」的当前任务。结项开始时盘点，主线交付、本地同步和运行交接均验证通过后执行删除。开发中、暂停、待验收、返工中的任务和其他历史任务不纳入本次清理。

涉及 [5274 统一验收](../README.md#业务任务统一验收5274) 时，按现有交接入口同步 5274，核实其健康、已交付版本退出组合且其他待验收版本仍在。5274 的固定工作目录、Compose 资源、验收库、媒体、退出账本和必要的迁移备份属于共享环境。

## 盘点当前任务的资产

1. 从实际任务 Worktree、任务记录和运行配置取得可验证的归属证据。沿这些记录查找仓库外的任务临时目录、归档、导出件、测试副本和 Docker 绑定挂载。逐项记录准确路径或资源标识、归属及使用方、删除或保留决定和依据。目录名、时间、端口或资源名称前缀只用于定位。
2. 检查未提交或未交付的代码、草稿、原始样本、验收资料及备份。已交付源码按远端主线上的提交找回。无法重建且只有一份的资料保留原件，已有可用副本的资料核对其位置和可读性。遇外部目录、挂载或符号链接，分别核实目标的实际路径与归属，避免把共享目录或链接目标带入删除范围。避免在盘点或清理报告中输出 `.env` 值或其他凭证。
3. 列出可删除的任务专属依赖副本、构建产物、临时文件、测试副本和已核对的重复资料。共享依赖缓存、必要备份、有效回滚资料和归属不明的资产保留。仅在目标范围已核实且其内容都可删除或已妥善保全时，整个移除目录或 Worktree。

## 核对并回收独占 Docker 资源

从任务运行记录或该 Worktree 的 `.env` 只取 `COMPOSE_PROJECT_NAME`，再结合 Docker 的 Compose 项目和工作目录标签、挂载、镜像 ID 及任务记录确认归属。核对当前任务与其他环境的引用，检查运行和停止的容器。Compose 项目标签证明创建归属，还需检查当前使用方及数据用途。

- **容器**：交接完成后，处理准确到容器 ID 的当前任务退役容器。若其可写层还有唯一资料，先保全。若交接已移除容器，复核即可。
- **镜像**：只移除可重建、明确由该任务独占、且没有其他环境引用的镜像，核对镜像 ID、所有标签和其他环境配置。Compose 中的通用 `mysql` 和 `maven` 镜像按共享依赖处理。
- **卷**：只移除无其他挂载方，且已核实可重建或有可用备份的任务专属临时卷。数据库、媒体和 `store-exit-ledger` 需要分别核对用途及恢复来源。带 `com.zdm.retained-data` 保留标记的卷，以及正式、共享、预览或仍用于回滚的卷都保留。Docker 绑定挂载目录按文件资产规则单独判断。

保留共享资源和无法重建的唯一副本。每次删除前复核准确对象和使用方。优先用普通 Docker 命令处理清单中的具体对象，避免全局 `prune`、批量 `docker compose down -v` 和强制删除。资源变化、仍被占用或无法证明安全时保留该项并记录原因，继续其他可安全清理的项目。

## 实测空间并报告

在第一次移除资源前和最后一次移除后，用 `df -Pk` 对同一组仍存在的宿主机路径采样。若现有运行交接会移除容器，首次采样提前到该步骤之前。至少检查工作区所在文件系统，若任务外部文件或 Docker 本地存储位于其他文件系统，也测量对应文件系统。选择同一挂载上的稳定路径，例如将被删除目录的父目录。记录采样时间、挂载点、清理前后的 `Available` 值和差值，单位为 KiB。同一文件系统的差值只计一次。Docker 报告的对象大小不加到宿主实测差值中。无法定位实际存储或测量失败时，记录具体原因。

清理后核对目标是否移除、保留的原件或备份是否仍可读取，以及受影响的共享环境是否健康。结项结果记录实际移除项、保留项及原因、各文件系统的实测空间变化。没有测到增长时按实测值报告。存在必要步骤未完成时，分别报告源码交付、运行交接和环境清理的状态。
