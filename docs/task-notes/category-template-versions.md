# 分类属性模板版本化

## 本轮边界

- 工作目录：`管理后台-worktrees/category-template-versions`，分支 `codex/category-template-versions`。
- 分类模板为平台公共数据，只允许平台身份维护；成品现货与配件按分类 scope 隔离。
- 仅保留成品现货模板／配件模板两个范围 Tab；进入分类直接查看属性模板。
- 每个分类维护一份属性草稿及已发布版本，草稿自动保存，发布时递增版本号。
- 已废弃独立标准规格模板：前端、服务、接口及权限目录已移除；V108 删除其记录、类型与关联列，保留 V107 迁移历史。
- 属性权限编码保持 `admin.product-data-center.category-attribute-template.<finished|accessory>.attributes.<action>`，既有属性授权不变。
- 销售属性角色保留，商品侧既有 SKU 业务不属于本次独立模板清理范围。
## 旧实现清理

仅保留新版属性模板。旧逐条绑定接口、实体、服务、未被路由引用的旧分类页面及权限别名已移除；V109 删除旧绑定表和选项值关联表。属性库引用统计、删除保护及租户清理改为使用新版模板。
新版草稿与已发布版本保留。构建规格标记集成在属性快照内，最多启用四个销售属性，随模板自动保存与发布。
商品侧的 SKU、价格、库存及历史商品数据不在本次清理范围，也不宣称商品已接入新版版本绑定。
已执行的迁移文件和 Git 历史保持不变。
## 当前功能目录登记（2026-09-09）

商品管理 → 商品公共基础数据 → 分类属性模板页 → 成品现货模板 / 配件模板。
每个 Tab 仅登记查看（view）、创建新版本草稿（create）、版本记录（history）。
create 同时控制创建、继续编辑、草稿内全部编辑与自动保存、发布，以及既有展示顺序调整；前后端使用同一权限。
history 控制版本记录及历史版本读取；仅 view 可查看最新已发布版本，不能读取草稿或历史版本。
原 save/publish/discard 和细分操作不再作为可分配条目，未自动扩大既有角色与终端授权。

版本记录的查看后增加复制操作，沿用 create 权限，不另设目录权限。复制已发布版本的完整 content 和 change_note 到单一草稿，原版本保持不变。已有草稿需确认覆盖并携带草稿 id/revision；并发变化拒绝覆盖。复制后进入草稿继续编辑，发布时沿用递增版本及配置校验。
